# design.md — book2qa 设计（v1 草案）

> 模块定位、能力边界、五个 skill 的职责划分与数据流。
> 配套契约见 [graph-spec.md](graph-spec.md)；质量判定见 [quality.md](quality.md)（待写）。
> 2026-10-27 起草，试点册：人教A版数学必修第一册。

---

## 1. 定位

**给学生的随身老师**：把一册教材变成能讲、能练、能记、能看见进步的学习伙伴。

它坐在 `book2md` 的下游：book2md 负责把 PDF 变成可信的 Markdown，book2qa 负责把这些
文本变成**学生能用的学习过程**。

| | book2md | book2qa |
|---|---|---|
| 输入 | PDF | md + 图片 + 公式 |
| 输出 | 忠实于原书的产物 | 讲解、练习、掌握度 |
| 使用者 | 转换者（老师/教研） | **学生** |
| 成败判据 | 与原书一致 | 学生学会了没有 |

**使用者已定：只有学生**，不做教师端、不做家长端。因此不单设 `report` skill，
学情信息作为 `review` 的输出小节。

## 2. 能力边界（红线，写进每个 SKILL.md）

1. **教材是唯一事实源**。AI 只做翻译与引导：可以把定义讲得更好懂、把解法拆得更细，
   但**不许补充教材里没有的结论**。检索不到就明说「本节未涵盖」。
2. **允许给完整解法**（用户已确认）。但输出必须固定为「思路 → 步骤 → 易错点 → 依据」，
   思路在前，学生抄答案时也会顺带看到思路。
3. **不替学生做作业**。同一道题连续追问三次以上仍要求"直接给答案"时，答复末尾加一句
   「建议先自己写到卡住的地方再看」，一句话，不说教。
4. **存疑内容必须标注**。`status: unverified` 的知识点，答复必须带「此处教材内容识别
   存疑，建议对照纸质书 P{页}」。
5. **不做拍照识题、不做语音**。输入是文本（可含 LaTeX）。这两项是工程投入大、且容易
   把产品拉成"搜题机"的方向，v1 明确不做。

## 3. 五个 skill 的职责与互斥边界

五个 skill 共用一套数据（图谱 + 原文 + 状态），差别在**触发意图**与**推进方式**。

| skill | 一句话职责 | 触发场景 | 谁来推进 |
|---|---|---|---|
| `book2qa-ask` | 解答一个具体问题 | 「这题怎么做」「什么是单调性」「P76 第 3 题」 | **学生**（碎片、随时） |
| `book2qa-learn` | 带学生按顺序学完一块内容 | 「带我学 3.2」「讲讲导数」 | **skill**（有节奏、有前置检查） |
| `book2qa-drill` | 出题、判分、讲错因 | 「出几道题」「考考我」 | **学生**（主动练） |
| `book2qa-review` | 按遗忘曲线安排复习 | 「今天该复习什么」「考前突击」 | **skill**（排程驱动） |
| `book2qa-build` | 把一册书建成知识点图谱 | 「把这册书建成知识点库」 | 维护者（非学生） |

**互斥规则**（防止 AI 选错 skill 或一题两吃）：

- 问一道**具体题** → `ask`；说"带我学/系统地讲" → `learn`。
- `learn` 内部的即时检测由 `learn` 自己判，**不切到 `drill`**（切换会打断节奏）。
- `drill` 出的题如果学生答错，错因分析在 `drill` 内完成，**不切到 `ask`**。
- `review` 到期清单里的知识点，学生若想听讲解，允许调 `ask` 的讲解能力，但**只讲不重排**。
- `build` 不面向学生，SKILL.md 的 description 里明确写"仅维护者使用"。

## 4. 数据流

```
book2md 产物（markdown.md + images/ + page_map.md）
        │
        ▼  build（含标题重建、公式文本化、图号映射、人工确认）
   data/graph.jsonl  ──┬──▶  ask     ──┐
   data/figures.json  ─┼──▶  learn   ──┤
   data/index/        ─┼──▶  drill   ──┤──▶  data/store.sqlite（掌握度/错题/排程）
   data/context.jsonl ─┘   review   ──┘        多轮对话上下文（最近 N 轮）
```

- `graph.jsonl` / `figures.json` / `index/`：**教材侧**，可重建，随书版本走。
- `store.sqlite`：**学生侧**，只增不重建，含个人数据，绝不外传。
- `context.jsonl`：多轮对话上下文（默认保留最近 10 轮），支持"那为什么这步是这样"的追问。

## 5. 五个 skill 的关键设计

### 5.1 ask

```
输入 → 定位（页码 / 知识点名 / 题干片段 / 图片）
     → 判断问题类型：概念不清 | 思路卡住 | 计算错误
     → 按类型讲（概念：>=2 种说法；思路：给下一步该想什么；计算：指出错行）
     → 输出协议：思路 → 步骤 → 易错点 → 依据（册 P页 §节 + 原文）
     → 一句自检问题（可选，学生可拒答）
```

定位失败时**不要硬猜**：回问"是第几页/哪一节"，比瞎答好。

### 5.2 learn

```
前置检查（测必要前置 1–2 题）→ 不会就先补
  → 分块讲（每块 <= 3 分钟，讲完立刻 1 题检测）
  → 答错：换讲法（换角度/换例子），不重复原话
  → 一节讲完：小结 + 写进度 + 给出下一块建议
```

硬约束：**一次不许讲完一整节**（信息过载等于没学）；前置未过不许硬推。

### 5.3 drill

```
选点（知识点/章）→ 选题（教材原题 / 变式，标注类型）
  → 学生作答 → 判分
  → 错因定位到具体知识点 + 具体错在哪一步
  → 入错题本（store）
```

变式题必须标「非教材原题」。判分必须给"哪一步错"，只给对错等于答案册。

### 5.4 review

```
取到期节点（简化 SM-2）→ 优先错题 → 快测（3–5 题）
  → 更新掌握度与下次复习时间 → 输出今日小结 + 下次时间点
```

一次不推太多（>10 个节点学生就烦了）；必须给出下次再来时间。

### 5.5 build

```
解析 markdown.md（标题重建，见 graph-spec §10）
  → 拆分知识点 → 挂原文锚点 / 图 / 公式（含 plain 文本化）
  → 生成前置关系（同节顺序 + 跨节规则 + 人工补）
  → 质量闸（公式可渲染 / 图存在 / 原文可溯 / 损坏公式标 unverified）
  → 输出 graph.jsonl + figures.json + build_report.md（待人工确认清单）
```

**必须人在环**：知识点边界、前置关系由人裁，AI 只出初稿。`build_report.md` 里
列出所有"AI 拿不准"的项目（标题歧义、锚点匹配度低、图号未找到）。

## 6. 技术风险与对策

| 风险 | 实测证据 | 对策 |
|---|---|---|
| 标题层级压平 | 必修一 `##` 436 个、`###` 0 个，章/节/思考/练习同级 | 五类正则分类 + 重建层级（graph-spec §10） |
| 噪音标题 | `## 思考`、`## da`、`## ••` 数十处 | 归入固定块或并入正文，不生成节点 |
| 章名拆行 | `## 第五章` 与 `## 三角函数` 分两行 | 续行合并规则 |
| OCR 损坏公式 | 化学书实测 2 条（嵌套 textcircled / 空 array） | 命中 `broken_formulas.tsv` 的节点标 `unverified`，答复必须提示 |
| 公式检索不到 | `$\sqrt{2}$` 搜不到"根号2" | 公式双轨：latex 显示 / plain 检索（graph-spec §6） |
| 图号与文件脱节 | 正文说"图3-5"，文件叫 `page_51_image_3.jpg` | build 生成 `figures.json` 建立映射，缺失的进待确认清单 |
| 定位不准导致编造 | — | 定位失败必须回问，不许用常识补 |

## 7. 分阶段与验收

| 阶段 | 范围 | 验收标准（硬指标） |
|---|---|---|
| **S1 建库** | 必修一 → `graph.jsonl` | 节点 70±10；每节点有 `pages` + `anchors`；公式 100% 有 plain；质量报告里 unverified 全部列明 |
| **S2 答疑** | `ask` | 20 个真实学生问题：答得出且**引用页码正确**（人工抽检 10 条）；答不出时如实说不会（零编造） |
| **S3 练习** | `drill` | 20 道题：判分准确率 ≥95%；错因能定位到具体节点（人工抽检 10 条） |
| **S4 复习** | `review` | 连续 2 周：到期清单不遗漏、不重复；掌握度变化与人工观察一致 |
| **S5 精学** | `learn` | 3 个学生试学一节：能完成且中途不跑题（主观 + 完成率） |

顺序：`build → ask → drill → review → learn`。learn 最复杂、依赖数据最全，放最后。

## 8. 测试与质量

沿用 book2md 的纪律：`run_tests.sh` 一键回归，不依赖网络的用例为第一梯队。

| 测试 | 测什么 |
|---|---|
| `test_graph_schema` | graph.jsonl 字段完整、id 唯一、prereq 指向存在 |
| `test_formula_plain` | 文本化规则表逐条（含反例） |
| `test_build_title` | 标题重建：章/节/子节/固定块/噪音五类 + 章名续行 + 编号缺空格 |
| `test_retrieve` | 真问题 → 命中正确节点（用图形锚点与公式关键词双向验证） |
| `test_store` | 掌握度更新、错题写入、排程计算（SM-2 边界） |
| `test_no_hallucination` | 给定教材未涵盖的问题，答复必须含"未涵盖"且不含具体结论 |

`test_no_hallucination` 是这套里最重要的一条：它守的是产品底线，不是代码正确性。

## 9. 命名与环境

- 包名 `book2qa`，CLI `b2q`，子命令 `build|ask|learn|drill|review`
- 环境变量前缀 `B2Q_*`（`B2Q_WORKSPACE` 等）
- 配置目录 `~/.book2qa/`
- 依赖：Python ≥3.13；无第三方依赖（检索用标准库实现 BM25，避免为检索引入重量级堆栈）
