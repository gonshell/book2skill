# pipeline.md — 数据形态与消费链路

> 回答三个问题：build 生成什么？这些东西算哪种知识库？五个 skill 各自怎么用？
> 契约细节见 [graph-spec.md](graph-spec.md)，代码分层见 [arch.md](arch.md)。

---

## 0. 一句话

**把教材切成 75 个"带指针的知识点"，每个知识点能指回原文那一段、指到那几道题、
指向它的前置节点；四个 skill 都从这同一个坐标系里取料，学生状态也挂在同一个坐标系上。**

不是向量库，不是问答对，也不是 RDF 三元组图谱——是**锚点图谱**（§3 逐项说明）。

## 1. build 生成什么：五个产物

| 产物 | 粒度 | 必修一量级 | 谁写 | 谁读 |
|---|---|---|---|---|
| `structure.jsonl` | 一行 = 一个**节/子节/章末附属**（不是知识点） | **63 行/册**（必修一实测） | 机器 | learn（按节取节点顺序）、ask（节号定位） |
| `exercises.jsonl` | 一行 = 一道**题**（含全局唯一 `eid`） | **584 条/册**（必修一实测） | 机器抽取 + 人认领 | ask（题号定位）、drill（出原题） |
| `figures.jsonl` | 一条 = 一个**图号 → 文件** | **106 条/册**（必修一实测；五册 ×5 估） | 机器 | 各 skill 插图 |
| `graph.jsonl` | 一行 = 一个**知识点** ★主产物 | **72–88 行** | 机器出初稿 + **人裁** | 四个 skill 全部 |
| `para_meta.jsonl` | 一行 = 一段（block_kind + owner_id） | **4333 行/册**（必修一实测） | 机器 | structure→extract 段间契约（RV-C8） |
| `build_report.md` | 人看的待确认清单 | 数十条 | 机器 | 维护者 |

`graph.jsonl` 是唯一的"知识本体"，其余四个都是它的**支撑索引或旁证**。

## 2. 结构组织：以节点为枢纽的四向引用

```
                    ┌──────────────────────────────┐
                    │  graph.jsonl（75 行，主产物）  │
                    │  id / title / type / summary  │
                    │  pages / errors / status      │
                    └───┬───────┬────────┬─────┬───┘
        anchors[].quote │       │prereq[]│     │ figures[]
        + physical_page │       │        │     │
                        ▼       │        ▼     ▼
              markdown.md       │   其他节点  figures.jsonl
              （原文，只读）      │   （有向图）   │
                                │              ▼
                    exercises[] │          images/*.jpg
                    （label/page）│
                                ▼
                        exercises.jsonl ──▶ 原文题干
```

四类指针**全是字符串**（quote、节号、题号、图号），没有一个偏移量、一个 id 之外的数字。
所以：人能手改、重跑不失效、不依赖任何模型。

### 一行真实样例（必修一 3.2.1 第一个节点）

```json
{"id":"M1-C3-S2A-K01","title":"函数单调性的定义","type":"concept",
 "book":"必修第一册","chapter":"第三章 函数的概念与性质",
 "section":"3.2 函数的基本性质","pages":[76,78],
 "summary":"用区间内任意两个自变量的取值比较函数值大小，定义增函数与减函数。",
 "anchors":[{"physical_page":76,
   "quote":"一般地，设函数 f(x) 的定义域为 I，区间 D⊆I……",
   "section_path":"第三章/3.2/3.2.1 单调性与最大（小）值","role":"definition"},
  {"physical_page":76,
   "quote":"你能举出两个特殊值满足 f(1)<f(2)，但函数不单调的例子吗？",
   "section_path":"第三章/3.2/3.2.1/思考","role":"motivation"}],
 "exercises":[{"label":"P77 练习 1","page":77,"quote":"根据下列函数图象，写出函数的单调区间。"}],
 "figures":["图3.2-1"],
 "formulas":[{"latex":"$f(x_1)<f(x_2)$","plain":"f(x1)<f(x2)"}],
 "prereq":["M1-C3-S1-K01"],
 "errors":["用两个特殊值代替『任意 x1<x2』判断单调性","忽略区间前提，直接说 f(x) 是增函数"],
 "status":"verified","built_at":"2026-10-27T17:00:00+08:00","built_by":"auto+review"}
```

这 15 个字段分三组，用途完全不同：

| 组 | 字段 | 谁读 |
|---|---|---|
| **定位**（指回原文） | `anchors` `pages` `chapter` `section` | skill 取原文段落用 |
| **教与练**（AI 的输入） | `title` `type` `summary` `formulas` `errors` `exercises` `figures` | 塞进 prompt 的料 |
| **排程**（机器判断） | `id` `prereq` `status` | 检索、前置检查、质量闸 |

## 3. 它到底是哪种知识库

先排除，再说结论。

| 候选形态 | 为什么**不是** |
|---|---|
| **向量知识库** | ① 数学符号嵌入极差：`$\sqrt{2}$` 与"根号2"在向量空间里可能很远，而这正是学生最常问的；② 命中了也给不出页码，无法满足"依据：P76 §3.2"；③ 学生问法极短（"这题怎么做"），语义信号弱，向量召回不稳；④ 引入 embedding 就破坏"零第三方依赖 + 纯本地"这条纪律 |
| **问答对（FAQ 库）** | 穷举问法不可能——75 个知识点 × 学生几十种说法；且问答对天然偏向"给答案"，与"思路置顶"的产品定位冲突 |
| **RDF 三元组图谱** | 教材知识不是三元组能表达的：单调性的定义需要一整段原文，不是 `(单调性, 定义, …)` 一个客体；强行三元组化会丢掉讲解所需的上下文 |
| **知识库 = 全册 markdown** | 单册 5–8 万字，直接丢进上下文虽放得下，但①无法保证定位到 P76，②做不了掌握度，③每次都要重读，成本高且不稳定 |

**实际形态：锚点图谱（anchored knowledge graph）+ 原文只读库 + 学生状态库，三件套。**

| 件 | 职责 | 存储 |
|---|---|---|
| 锚点图谱 | 知识点是什么、考什么、前置是什么 | `graph.jsonl`（75 行） |
| 原文只读库 | 讲的时候引哪一段 | `markdown.md` + `images/`（只读，不改一个字） |
| 学生状态库 | 谁学到哪、错在哪、下次什么时候复习 | `store.sqlite`（只增不重建） |

**为什么是"图谱"而不是"碎片集合"**：因为 `prereq` 让它成为有向图，learn 才能做前置检查、
review 才能按依赖顺序排程；而 `anchors` 让它不脱离原文，AI 不敢编。

## 4. 检索：先判断学生问的是什么，再四路并行召回

**上一版在这里写成"精确 → 术语 → 题干 → 回问"的顺序回退，且拿「P76 这个单调性……」当例子。
那两处都是错的**：真实学生十句里有八句不含页码、题号、节号，顺序回退等于先把八成问题判成未命中。

现行做法（详见 [retrieval.md](retrieval.md)）：

1. **先分问题类型**：概念追问 / 卡题 / 判自己答案 / 方法清单 / 范围过宽 / 排程 / 承接。
   类型只决定"输出模板"和"召回侧重"，不决定答不答。
2. **四路并行召回**：术语路（title+aliases+summary+errors+plain 公式）、
   **段落路（节内正文段落，节点之外的讲解也在这里）**、结构路（页码/题号/节号，精确相等）、
   **向量路**（bge 语义近邻，治同义改写；模型未装则自动降级三路）。
3. **RRF 融合取 top5**，每个候选带命中理由；段落可以命中"提问块"而**不属于任何节点**。
4. **兜底三级**：强命中直接答 / 弱命中先问"你问的是不是 X" / 全空则回问给 3 个切入点。

索引与五场景的取料/排序差异见 [serving.md](serving.md)；`index/` 由 S2 的
`b2q index` 建（S1 不建，arch.md §9.3 口径不变）。

## 5. 五个 skill 怎么用这些数据

**共同前提**：每次只取 top1–3 个节点 + 命中段落进上下文，绝不整库喂。
这是"图谱"而非"全册丢给 AI"的意义。

**输出模板必须按问题类型分叉**（retrieval.md §6）：把"思路→步骤→易错点→依据"套到
「为什么一定要说任意」这类概念追问上，等于答非所问——那种问题要的是**动机 + 反例**。

### 5.1 `book2qa-ask` — 答一道题 / 一个概念

```
学生问（通常不含页码）
  → 判类型（retrieval.md §2）+ 四路召回 → 候选节点/段落 top5
  → 组装料：H.summary + anchors（优先 role=motivation）+ 命中段落原文
            + H.formulas.plain + H.errors + H.exercises
  → 按类型选模板输出（概念追问：直答→教材原话→反例→易错点→依据）
  → 写 store.sqlite（命中节点、问的类型） + context.jsonl（支持"那为什么这步"）
```

要点：**prompt 里明确"只许用给定原文，超出的说『本节未涵盖』"**——这是把红线 1 变成工程约束，
不是靠 AI 自觉。全空时给 3 个切入点回问，不猜、也不问"是第几页"（学生答不上来）。

### 5.2 `book2qa-learn` — 带学一节

```
"带我学 3.2" → structure.jsonl 取该节 → graph 筛出该节节点，按 id 排序
            → prereq 检查：前置节点在 store 里 mastery < 阈值就先补
            → 逐节点讲（每块 ≤3 分钟）→ 讲完立刻用 H.exercises 出 1 题
            → 答错：换讲法（换角度/换例子），不重复原话
            → 全节讲完：小结 + 写 store 进度 + 给下一块建议
```

要点：`prereq` 是这里唯一的硬依赖；没有它，"带学"会变成"照着目录念"。

### 5.3 `book2qa-drill` — 出题判分

```
选点：store 里 mastery 低 / 最近错题所属节点
   → 出题：优先 H.exercises 的教材原题；不够则按 H.errors 反向造变式（标"非教材原题"）
   → 判分：拿 H.errors 当错因映射表，必须说出"错在哪一步"
   → 写 store：attempts + wrong_book
```

要点：**`errors` 字段是判分的依据**，没有它，判分只能给对错，等于答案册。

### 5.4 `book2qa-review` — 按遗忘曲线安排

```
"今天该复习什么" → 不检索，直接读 store.sqlite 的 due 列表（SM-2）
   → 优先错题节点 → 出 3–5 题（用 H.exercises 原题）
   → 更新 mastery 与 next_due → 今日小结 + 下次时间点 + 学情小节
```

要点：`review` 不生成新内容，只调度——"讲什么"调 ask 的能力，规矩是**只讲不重排**。

学生中途说"我忘了诱导公式"时，走检索 → 命中节点 → 用**复习模式**讲：
**≤3 句话 + 立刻 1 题验证，禁止长篇**（复习要的是"唤起"，不是"重学"；讲长了学生就放弃复习了）。
这条是 SKILL.md 的硬约束，不是建议。

### 5.5 `book2qa-build` — 生产者

只写不读：产出 §1 五个产物，人是最终裁决者（边界、命名、`status`）。

## 6. 两条完整链路（真实问法）

### 6.1 学习时：概念追问

> 学生：「单调性为什么一定要说"任意"两个数？」（**没有任何页码**）

```
① 判类型：'为什么' + '一定要' → concept_why
② 四路召回：
   R1 术语：'单调性' 命中 title（×3 权重）；'任意' 命中 errors[0]
            「用两个特殊值代替『任意 x1<x2』判断单调性」→ 节点 K01 分最高
   R2 段落：'任意' 命中定义段 + 紧随的「思考」块
            「你能举出两个特殊值满足 f(1)<f(2) 但函数不单调的例子吗？」← 教材自己的动机
   R3 结构：无信号，不参与
   R4 向量：'增啊减啊' 类口语改写由语义近邻兜底（本句 R1 已强命中，R4 佐证）
③ 融合 → 主依据节点 K01 + 提问块段落（P76「思考」）
④ 按 concept_why 模板输出：
   直答：因为"任意"排除"挑一组好数恰好成立"
   → 教材原话（引定义段 + 思考块）
   → 反例：f(x)=x² 在 [-1,2] 上，取 x1=1,x2=2 有 f(1)<f(2)，但整体不单调
   → 易错点：引 errors[0]
   → 依据：必修一 P76 §3.2.1（含「思考」）
⑤ 落库：store 记一次 concept_why（不计掌握度）；context 留 10 轮
```

两个要害：**"任意"这个词在两处都有**（节点 errors 与教材思考块），只查节点层会丢掉教材原话；
**输出模板不是四步解题式**，是先直答、再反例。

### 6.2 复习时：只说"我忘了"

> 学生：「诱导公式我忘了」（复习阶段，第 3 天）

```
① 判类型：'我忘了' + 当前在 review 会话 → 排程域内的求讲
② 召回：'诱导公式' 精确命中 3 个节点（M1-C5-S3-K01..K03）
③ 复习模式输出（≤3 句 + 1 题）：
   「一句话：把任意角的三角函数化到锐角，符号看象限。」
   「出题：化简 sin(π+α)·cos(-α)。」（取 H.exercises 原题）
④ 学生答完 → 更新 mastery / next_due → 回到 review 的到期清单
```

**不许在这里讲十分钟推导**——那是 `learn` 的事。复习阶段讲长了，学生当天就不再打开。
两个 skill 的区别不在"内容多少"，而在**同一个知识点被切成多长的块**。

上面两条链路里，**AI 没有一句是自己编的**：讲法是它的，事实全部来自命中段落的原文与 `errors`。

## 7. 边界

| 不做 | 何时可能做 |
|---|---|
| 向量检索（R4） | **已定版进 v1**（serving.md，2026-11-01）：bge-small-zh ONNX，模型未装自动降级三路。若融合后 Recall@5 仍不达标 → 升 bge-base 或调场景加权，签名不变 |
| 跨册知识关联 | 五册都建完后，加 `related` 弱关系边 |
| 自动出章节摘要 | 摘要必须落在节点上（`summary` ≤60 字），不要"全章摘要"这类无锚点产物 |
