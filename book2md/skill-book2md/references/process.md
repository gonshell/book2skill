# 转换流程方法论（references/process.md）

按需加载：触发时只读 SKILL.md；进入复核裁定环节才读本文件。

## 一、标准流程总览

```
onboard（新书接入）→ extract（网关抽取）→ run（质量门流水线）
  → verify_delivery（交付核验）→ adjudicate_sheet（复核表）
  → 人工对照 PDF 裁定 → overlay_scaffold（结论固化）→ 交付汇报
```

## 二、C 档人机分工（核心纪律）

| 谁 | 干什么 |
|---|---|
| CLI（确定性代码） | 抽取、修复、渲染、扫描、报告——快且稳，不临场发挥 |
| 你（对话助手） | **判断**：联网核对教材官网、目检 PDF、多源交叉验证、与用户确认 |
| 用户 | 终审：C 档裁定、规则取舍、是否接受交付 |

## 三、裁定流程（④固化）

1. `verify_delivery.py` 通过后，跑 `adjudicate_sheet.py` 生成复核裁定表
2. 对表中每条存疑项：打开 PDF 对应页目检 → 需要时查教材官网/多源交叉验证
3. 裁定结论填入表格（正确 / 误报 / 存疑）+ 备注；**与用户确认结论**
4. `overlay_scaffold.py` 把裁定登记为书目覆盖层（overlays/<book>/）
5. 若裁定揭示**通用规则缺陷**（不是单本书的问题）：报告用户 → 修核心包
   `packs/<学科>/` 规则或引擎，配对账测试——严禁只在对话里绕过

## 四、汇报规范

- 产物清单用 present_files 呈交（HTML 双版 + markdown 为主交付物）
- 必报：issues 分级计数、质量门各关状态、C 档剩余数
- 必提醒："C 档内容未经人工复核不得视为定稿"
- 必提醒（欠账状态）：网关侧功能实测情况（见 AGENT.md 台账）
