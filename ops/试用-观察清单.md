# 试用运营 — 观察清单（老师/运营侧）

> 试用周期建议 2 周。本文档 = 试用期间每天/每周看什么、怎么处置。

## 每天（2 分钟）

```bash
ssh localgpu "wc -l ~/book2qa/data/request_log.jsonl"     # 用量是否在涨
```
- 请求数连续 2 天不涨 → 找学生聊一句（通常是技能没装上或忘了用）

## 每周（15 分钟，出周报）

1. **拉日志 + 出巡检报告**：
   ```bash
   scp localgpu:~/book2qa/data/request_log.jsonl book2qa/data/inspect/
   cd book2qa && python scripts/inspect_report.py
   ```
2. **看三个数**（报告 §1）：
   - `none` 占比 >10% → 检索有系统性缺口，优先处置（补 aliases / 加 gold）
   - `low` 聚类里出现**同一问法重复多次** → 高优先：学生真问、系统真没答好
   - `high` 占比升 → 整体健康
3. **学情抽样**（store.sqlite）：
   ```bash
   sqlite3 ~/book2qa/data/store.sqlite \
     "SELECT node_id, COUNT(*) c, SUM(correct) ok FROM attempt \
      WHERE account_id LIKE 'stu-%' GROUP BY node_id ORDER BY c DESC LIMIT 10;"
   ```
   错误率最高的节点 → 检查其 errors 是否写得太泛
4. **周报三段式**（发用户）：用量 / 未命中 Top5 + 处置 / 学生错点 Top5

## 处置动作对照

| 现象 | 动作 | 落点 |
|---|---|---|
| 某节点被反复问到但命中错 | 补 aliases（Excel 或直接改 candidates） | 重跑 graph+index+发布 |
| 合理问法但 confidence=none | 加进 eval_gold 并修检索 | 重跑评测，Recall@5 不许降 |
| 学生说"图不对/看不清" | 核对 figures 映射 | figures.jsonl 修正 |
| 学生说"题出重复了" | 检查 drill 出题去重（v1 未做跨会话去重 → 记为改进项） | 下版本 |

## 试用期结束的验收（roadmap M4）

- [ ] ≥3 名学生各使用 ≥5 天
- [ ] 首份周报产出并处置（aliases/gold 至少各补 5 条）
- [ ] 学生主观反馈收集（一句话即可）
- [ ] 备份链跑过一次 `--full`
→ 达标后打 **v0.8.0**，M5（公网/豆包）由用户决定是否触发
